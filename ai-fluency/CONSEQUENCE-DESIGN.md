# Consequence-based phone workflows

The three authored simulations ask learners to predict, choose, inspect a result and revise. All branches can continue. A completed decision is not automatically a correct decision.

- **Opportunity:** a polished claim leads to a practical follow-up. Learners compare data inputs, practise checking records and attempt a changed sheet without the chat. First answers remain in the learning record after retries.
- **Learning:** model answers and guided attempts are plausible strategies. Independent changed examples supply evidence about what the learner can do. Selecting tutoring does not automatically earn a learning-success score.
- **Poster:** the actual image retains or omits facts based on choices. Caption-only repairs cannot fix image-only reposts. Updating one version can leave conflicting destinations. Returning to repairs clears the later release judgement so the new versions must be assessed again.

All outcomes are fictional teaching examples, not claims about hiring odds, learning gains or social reach. Privacy comparisons illustrate these particular inputs and tasks, not a universal assertion that context never helps.

## Teaching

Allow 3 minutes for setup and 42 for the eight decisions. Before each action, partners predict an outcome; afterwards they point to evidence and finish “This changes ___ because ___.” Swap the phone after each decision. During Notes tests, each partner decides independently before discussing. A teacher should listen to explanations: multiple-choice completion alone is not evidence of fluency or professional readiness.

The original progress format is archived under `dialogue-phone-lab-archive-{journey}` when a learner opens version 2; new progress starts separately. Records remain local to the browser. There is no upload or live AI service.

## Validation

Run `node ai-fluency/consequence-check.cjs`, `node ai-fluency/phone-check.cjs`, and `node ai-fluency/check.cjs`. The consequence test covers all 50 choices, comparison gating, first-answer preservation, poster states and progress migration. Browser verification covers the three journeys, repair/retest, source navigation and a 390 × 844 mobile viewport. Classroom effectiveness still requires a learner pilot.
